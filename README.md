# 准镜 ZhunJing · 评测平台

**把地址贴进去，跑一遍真实环境的检查，拿到一份每条结论都能亲自核验的报告。**

准镜是一款面向真实环境的质量评测工具：它像真实用户一样打开、点击、输入，再对每一条结果逐一判定，最终交付一份**带完整证据链的报告**——报告里的每一个结论，都能逐层展开到原始证据，任何人都能离线复核。

**不追求「测得更多」，只追求「测得的结果别人能验」。**

---

## 一、它为你解决什么

评测报告常常只给结论、不给依据：分数好看，却没人能复查，也没人敢直接采信。准镜把「可验证」放在第一位。

| 常见困扰 | 准镜的做法 |
| --- | --- |
| 报告只有结论，无法复查 | 每个结论都能逐层下钻到证据，支持离线核验 |
| 评分靠推断，和真实使用对不上 | 像真实用户一样真实执行，结论只由真实结果决定 |
| 换个人、换个时间再跑，结果对不上 | 同一对象、同一标准，结果可复现 |
| 多团队数据互相可见 | 每个工作区数据严格隔离，互不可见 |

准镜仅用于对**自有或已获授权对象**的测评。

## 五、版本记录

### v8.3.16
- **发布流程此前有一处会拿错文件**：上传安装包的脚本按错误目录去找产物，实际会去报「文件不存在」。也就是说这条发布链路在上一版上**从未真正跑通过** —— 发行页上的附件是别处补上的。现已改正并加了构建前的自动检查
- **校验值不再会写错**：发行说明里原先把某个旧版本的校验值**写死**了，导致每发布一版，页面上公示的校验值都是上一个版本的。用户按它比对必然失败，而失败看起来像「文件被篡改」。现改为发布时自动读取当版的真实校验值，读不到就中止发布 —— 宁可不发，也不发错的
- **版本号从此由机器守着**：版本号此前分散在 6 处手工维护，已经出现「启动窗口显示的还是很早的版本号」这类情况。现以工程配置为唯一基准做自动核对，并接进了构建流程：一旦某处版本号没同步，**直接拒绝构建**，不会再产出与说明不一致的安装包
- **上手指引改为真实形态**：原先指引用户「解压 zip 包」，但实际交付早已是单个 exe 文件、根本不需要解压，照着做只会找不到文件。现按真实交付方式改写

### v8.3.15（安装包待发布）
- **历史报告不再查不到**：与上一版修复的「运行列表」是同一个毛病 —— 报告列表此前也只显示最近的一批，条数超过上限后更早的报告会直接从界面上消失、同样没有任何翻页方式能找回。现已一并支持分页，并显示「共 N 条 · 当前第几页」，逐页可回溯到最早一份报告
- **为什么这条更要紧**：运行丢了还能重跑，**报告丢了就没了** —— 它是已经得出的历史结论。报告找不回，等于「每条结论都能核验」这句话在产品自己这里破了案
- **校验文件换机也能用**：随包提供的校验清单此前记录了本机的完整路径，换一台电脑、换一个命令行环境就无法校验，等于没有。现改为只记录文件名，任何平台按标准方式都能直接校验

### v8.3.14（源码已更新，安装包待发布）
- **审计记录被删也能发现（重点修复）**：此前若有人删掉了**最新一条**操作记录，完整性校验仍会显示「通过」—— 因为剩下的记录本身依然自洽。这是「可核验」最不该有的漏洞：删掉不利于自己的记录就能绕过检查。现已补齐检测，并且校验基准会跨重启保留，**删记录、重启后再看，仍会被发现**
- **历史数据完整性修复**：早期版本升级时部分历史记录的编号口径不统一，导致完整性校验对个别工作区误报异常。现已统一并逐个复核，**现存全部工作区校验均正常通过**
- **正常操作不会再被误报**：修复校验逻辑后曾出现「每次正常操作都被当成异常」的假警报（假警报比不校验更糟，会让真实警报被忽视）。现已按「只追加、不可改写」的正确判据重做，**正常操作零误报，删改仍必报**

### v8.3.13（源码已更新，安装包待发布）
- **历史运行不再查不到**：运行列表此前只显示最近的一批，条数超过上限后更早的记录会直接从界面上消失、也没有任何翻页方式能找回。现已支持分页，并明确显示「共 N 条 · 当前第几页」，逐页可回溯到最早一次运行
- **登录设备与过期会话处理更快**：会话数量累积后，登录时的会话校验与过期清理会明显变慢；现已补上缺失的数据索引，这类操作不再随会话数增长而劣化

### v8.3.12
- **可核验从「能看」变成「能做」**：运行详情页新增「主动验算」——点一下，由准镜当场重新计算本次运行的证据完整性，而不是把当初存下的结论再念一遍；结果与页面展示值逐字对照，对不上就明确标红提示「请勿作为可信依据」。此前这一能力后台已具备，界面上却没有入口，「别人能验」一直只是句口号
- **数据看得见了**：概览页新增「资产量化」与「运行健康度」两块，把你已积累的断言数、通过/失败、观测、证据块、报告数真实列出来，并区分「环境受阻」与「产品缺陷」——后者才是准镜要回答的核心问题，此前统计了却无处可见
- **报告可直接交付**：新增「导出报告文件」，导出 Markdown 交给对方，**对方无需登录即可离线阅读与复核**。此前「分享」按钮复制出的链接只在你自己的电脑上打得开，交付这一步实际是断的；现在链接仍给，但会如实提示需在已登录本机打开
- **时间显示修复**：项目、目标、报告、登录设备等处的时间此前会**整体偏 8 小时**（时区被抹掉）。既然主打「可核验」，时间不可信会直接削弱这一主张，现已全部修正
- **登录不再卡顿**：密码校验此前会短暂阻塞全站并发请求（多台设备同时操作时更明显），现已改为不阻塞，整站响应更稳
- **历史数据修复与治理**：修复了部分历史记录完整性校验异常、以及误删运行后残留的孤立数据会干扰通过率的问题；已清理过期会话与残留数据
- **异常不再静默**：此前若某个页面加载出错，界面会直接空白且无任何提示；现在会明确告知出错并提供重试入口

### v8.3.7
- **报告可导出归档**：报告支持导出为 Markdown（原仅 JSON），可直接归档、转发与二次核验，兑现「测得的结果别人能验」
- **证据到期自动清理**：按会员档位（免费 30 天 / 专业 365 天 / 团队 1095 天）到期自动物理清除运行的证据产物，隐私承诺从「口头」变为「真实执行」，且清理动作留有可追溯记录
- **报告查看修复**：修复报告详情页指标显示为 0 的问题，现在如实呈现断言数、通过率与判定
- **离线编辑修复**：修复以本地文件方式打开页面时，「保存修改」可能被浏览器预检拦截的问题

### v8.3.6
- **报告可信度加固**：审计记录的完整性校验修复 —— 任何一条记录被改动都能被立即发现，不再出现「校验状态未知」；归档、恢复、删除等每个动作后校验都保持通过
- **编辑保存修复**：项目 / 目标 / 场景的「保存修改」此前可能不生效，现已修复
- **会员权益修复**：取消订购后权益状态即时归位，不再出现「已取消却仍显示专业版」的情况
- **登录设备管理修复**：会话（登录设备）列表信息恢复正常展示
- **运行引用校验**：触发来源引用的历史运行必须真实存在，杜绝伪造引用
- **归档运行阻断**：已归档的项目无法再被直接触发运行，须先恢复
